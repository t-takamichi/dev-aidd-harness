# ワークフロー詳細

## ファイル構成

`{プロジェクトDir}/` 直下（本番。コミット対象）

| ファイル | 内容 | 作成者 |
|----------|------|--------|
| `README.md` | タスク一覧 | メイン |
| `{ID}-{slug}/task.md` | タスク詳細 | メイン |
| `requirements.md` | 要件インベントリ。`R-ID \| 要件 \| 出典（章・節 or Q#） \| 状態` の表。状態は空 or `廃止` | メイン |
| `decisions.md` | 決定ログ。`Q# \| 質問 \| 回答 \| 日付` の表。質問ゼロでも空の表で作る | メイン |

`_work/`（作業用。コミット不要）

| ファイル | 内容 |
|----------|------|
| `design-input.md` | 設計書を本文で受け取った場合の保存先 |
| `investigation-{観点slug}-{範囲}.md` | 調査結果（design-investigator が書く）。観点slug: `requirements` / `data-if` / `code` / `cross`。範囲: 章番号 or `all` |
| `draft/` | ドラフト。本番と同じ構成で `README.md` と `{ID}-{slug}/task.md` を置く |
| `review-{n}-{群}.md` | n 回目のレビュー結果（レビュアーの返答をメインが保存）。群: `all` / `T01-T05` など |

## エージェントへの依頼テンプレート

サブエージェントは会話を読めない。次の項目をすべてプロンプトに含める。

### design-investigator

```
設計書: {絶対パス}（対象範囲: {章・ページ範囲 or 全体}）
対象MSルート: {絶対パス}
観点: {requirements | data-if | code | cross}
書き出し先: {_work/investigation-{観点slug}-{範囲}.md の絶対パス}
返答: 要約（15行以内）と不明点だけ返す。詳細は書き出し先に書く。
要件候補: 観点が requirements のときは、要件候補を `要件 | 出典` の表で書き出し先に含める。
```

| 観点 | 調べること |
|------|-----------|
| requirements | 機能・振る舞い・非機能要件、章構成、用語。要件候補の抽出 |
| data-if | DB スキーマ、API、イベント、外部連携の入出力定義 |
| code | 影響を受ける既存実装、再利用できる共通部品、命名・構成の慣習 |
| cross | 認証認可、エラー処理、ログ、性能、移行・互換性 |

設計書が大きい場合は観点に加えて章単位でも分ける（同名ファイルにならないよう範囲を名前に入れる）。

### task-draft-reviewer

```
レビュー回: {n}回目
設計書: {絶対パス}（読む範囲: {章・ページ範囲 or 全体}）
要件インベントリ: {requirements.md の絶対パス}
決定ログ: {decisions.md の絶対パス}
ドラフト: {_work/draft/ の絶対パス}（対象: {全体 | T01〜T05 の詳細}）
フォーマット: {task-list-format.md の絶対パス} / {task-detail-format.md の絶対パス}
機械チェック結果: {validate-tasks.py の出力}
前回の指摘: {review-{n-1}-{群}.md の絶対パス。1回目は「なし」}
```

設計書が大きい場合は読む範囲を章単位で指定し、インベントリの漏れ確認は1回目だけ依頼する。

## 小規模ルート（タスク5件程度）

- 調査は `design-investigator` 1体（観点は全部まとめて依頼）。
- 要件インベントリ・決定ログは省略しない（根拠と網羅の基準になる）。
- レビューは1回。blocker が出た場合のみ修正して再レビューする。

## 更新モード

`{プロジェクトDir}/README.md` が既にあるとき（設計書の改訂・追加要件など）。

1. 旧設計書と新設計書の差分範囲を特定し、その範囲だけ `design-investigator` で調査する（旧設計書がなければ既存の requirements.md の出典と突き合わせて範囲を決める）。
2. `requirements.md` を更新する。新規は新 R-ID で追加、設計書から消えたものは状態を `廃止` にする。既存 ID は変えない。`decisions.md` も追記のみ。
3. 既存の README.md と全 `task.md` を `_work/draft/` にコピーし、影響するタスクだけを修正する。新規タスクは新 ID、不要になったタスクは状態 `廃止`。README のステータスは `draft` に戻す。
4. 以降は通常の手順3〜7。**本番への反映は手順7の承認後のみ**。既存タスクの変更は差分としてユーザーに示す（人が手で編集した内容を上書きしないための確認を兼ねる）。

## ステータスの更新

- `draft`: ドラフト作成中（更新モードに入ったときも `draft` に戻す）
- `reviewed`: レビューで blocker / major が 0 件になったとき（メインが `_work/draft/README.md` に付ける）
- `approved`: ユーザーが承認し、本番へ反映するとき（メインが付ける）
